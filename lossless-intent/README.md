# 无损传达 Skill

版本：1.0.0  
安装标识：`lossless-intent`  
用途：默认识别重要理解歧义，用整体小样、局部纠偏和共识交接减少需求走样。

这是一份可安装的指令型 Skill，不是网站、常驻程序或项目管理系统。无需为它配置数据库、API 密钥或额外联网服务。检索、图像生成、文件操作等使用所在 AI 工具已经提供并获授权的能力，不会因安装本包凭空获得。

“无损传达”是名称，不承诺百分之百还原想法。实际自动调用、文件访问及生成能力取决于宿主和设置。本包未在你的电脑上安装，也没有完成各宿主中的独立模型行为测试。

## 1. 它会怎样工作

有重要歧义时自动展示整体小样 → 用户指出差异 → 只修正关键分歧 → 回放完整体验 → 交接当前共识 → 重大变化时局部重新对齐。

明确小任务直接完成；不固定三轮；不反复询问已有答案；允许两种方案都提供；认可一个局部不会扩大为全案批准或发布许可。执行失败不归咎用户表达。

默认遵循对话语言，优先通俗表达。用户说不清专业词汇时，通过实例、对照或可用的视觉材料帮助判断，不要求先写标准需求文档。

```text
lossless-intent/

  README.md                        安装与使用说明

  assets/consensus-template.md     需求共识单模板
  references/protocol.md           按需读取的详细协议
  references/examples-and-lessons.md  两组测试经验与示例
  tests/acceptance-cases.json      24 个待执行行为用例
  tests/validate_skill.py          只读静态检查器

```

正常对话只需核心规则，其他材料按需读取，不默认加载整套测试。安装时复制整个 `lossless-intent` 文件夹，不能只复制 `SKILL.md`。

## 3. 在 Codex 中安装

以下目录和调用方式依据 2026-10-16 核对的 OpenAI 官方说明。[来源 2]

### Windows 个人安装

1. 解压安装包，找到直接包含 `SKILL.md` 的 `lossless-intent` 文件夹。
2. 将整个文件夹放到当前运行 Codex 的用户主目录下：

```text
%USERPROFILE%\.agents\skills\lossless-intent\SKILL.md
```

在文件资源管理器地址栏输入 `%USERPROFILE%` 可以打开当前 Windows 用户主目录。不存在的 `.agents`、`skills` 文件夹按需创建。最终应该是 `skills` 里面直接放 `lossless-intent`，不要多嵌套一层压缩包文件名。

若同名文件夹已经存在，先停下来检查它是否为旧版本；不要直接覆盖。要更新时先备份旧版并核对，再由你明确确认替换。无需管理员权限，不需要修改系统安全策略。

3. 让 Codex 重新识别 Skill。没有出现时重启 Codex，再使用 `/skills` 查看，或在对话中明确点名：

```text
$lossless-intent 帮我检查这个想法，先展示一个能看出整体方向的小样。
```

个人目录安装用于当前用户的多个项目。不希望全局提供时，可以仅放到目标项目的 `.agents/skills/lossless-intent/`；两种位置选一种，避免同名重复安装。若 Codex 实际运行在 WSL、远程主机或容器，应安装到那个环境自己的用户／项目目录，不能把 Windows 主目录当成它的运行目录。[来源 2]

### 默认自动调用

`agents/openai.yaml` 已设置：

```yaml
policy:
  allow_implicit_invocation: true
```

这允许 Codex 在任务匹配描述时自行选择此 Skill，不是强制每条消息都执行，也不保证每次匹配成功。没有默认修改全局 `AGENTS.md`、配置文件或其他 Skill，不增加强制钩子。[来源 2]

可先在新对话自然输入“我想做一个工具，简单好用，但还没想清楚”，观察是否自动给出整体小样。再输入一次明确的小修改，检查它是否直接完成。实际是否触发应以宿主显示或可用记录为准，不能仅凭回答相似就认定已加载。

## 4. 在 Claude Code 中安装

依据 2026-10-16 核对的官方说明，可以将整个目录放到个人 Skill 目录，或只放在某个项目中。[来源 3]

```text
个人：~/.claude/skills/lossless-intent/SKILL.md
项目：<项目目录>/.claude/skills/lossless-intent/SKILL.md
```

`~` 表示实际运行 Claude Code 的当前用户主目录。Windows 原生环境对应当前用户主目录；WSL、远程或容器使用各自的主目录。不要直接把 `<项目目录>` 当成真实路径。

手动调用示例：

```text
/lossless-intent 帮我把这个模糊想法整理成可判断的小样。
```

本包不关闭模型自动调用。Claude Code 根据描述决定是否适用；`agents/openai.yaml` 是可选的 Codex 元数据，不作为 Claude Code 自动行为的保证。[来源 3]

## 5. 其他 AI 工具

本包以 Agent Skills 标准的 `SKILL.md` 和相对路径组织。[来源 1] 支持该标准的工具可按其官方安装入口或目录使用，仍需检查该工具的版本与自动触发规则。不要猜它的安装目录，也不要一键复制到所有扫描到的路径。

如果某个对话工具没有原生 Skill 安装入口，可以在允许上传或引用文档的会话中提供 `SKILL.md` 及所需参考文件，并明确要求按其协作。这个办法只是当前会话的指令使用，不是原生安装、永久记忆或跨会话自动启用。

本交付物是独立 Skill 源码包，不是某个平台应用市场的已发布插件。分享或上架时还需对应平台要求，本次不创建商店条目、不提交仓库、不分配未经确认的开源许可证。

## 6. 和其他 Skill 配合

本 Skill 只管意图和共识。写代码、生成图片、制作 PPT、实际测试仍交给原来的工具或专业 Skill。已有需求文件和设计确认可以直接复用，不并行创建重复澄清流程。

后续执行出现偏差时，可直接说：

```text
用无损传达 Skill 检查当前偏差。复用已确认的要求，只指出发生变化的地方，不重新询问整套需求。
```

交接模板默认在当前对话使用。需要写到项目文件或传到另一个工具时，只写入、分享已经获授权且必要的信息；不要自动复制完整历史或敏感材料。

## 7. 验证与限制

本包的静态检查只验证结构、配置、引用和完整性等；实际模型是否遵循规则、自动调用是否稳定以及对用户的收益，需要独立测试。

[测试说明](tests/README.md)列出方法，24 个行为用例均标为 `NOT_RUN`，没有伪装成已通过。日常使用无需运行测试脚本。

本 Skill 是协作约定，不是安全沙箱或强制权限系统；仍以宿主保护措施和用户授权为准。不能保证所有 AI 工具原生支持，不能保证“安装后每条消息必定触发”，不能用小样确认代替文件和功能验证。
